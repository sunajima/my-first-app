# こつこつ家計簿

日本語で使えるシンプルな家計簿です。React・TypeScript・Vite で作成しています。PC とスマートフォンに対応し、有料 API や外部サービス、アカウント登録は不要です。

## 起動方法

Node.js 22.12 以上（推奨：Node.js 24 LTS）と npm をインストールしてください。

```bash
cd /workspace/my-first-app
npm ci
npm run dev
```

自分の PC にコピーした場合は、コピー先のフォルダに移動してください。ターミナルに表示されたアドレスをブラウザで開きます。停止は Ctrl+C です。

## 操作方法

1. 「支出」または「収入」を選びます。
2. 日付・金額・カテゴリを入力します。メモは任意（100 文字まで）です。
3. 「記録を保存する」を押します。金額は 1〜999,999,999 円の整数で入力します。
4. 「表示する月」を変えると、その月の収入・支出・差額と支出内訳の円グラフを確認できます。登録時には登録した日付の月に切り替わります。
5. 「今月の記録」のカテゴリを選ぶと一覧を絞り込めます。合計とグラフは、その月全体の集計のままです。
6. 記録の右の「×」を押し、確認画面で承認すると削除できます。

カテゴリは収入・支出それぞれに用意した固定の選択肢です。グラフの横には金額と割合を文字でも表示します。割合は丸めているため合計が 100% にならない場合があります。

## データの保存について

保存先は、使用しているブラウザのローカルストレージです。同じブラウザ・同じアドレスで再度開くと記録を復元します。端末間の同期やバックアップ・書き出し・編集機能は、最初のバージョンにはありません。

ブラウザのデータ削除やプライベートモードの終了などで記録が消えることがあります。ポートやドメインを変えると保存領域も変わります。大切なデータの唯一の保管場所にはせず、必要に応じて手元にも控えてください。

保存ができない場合はエラーを表示し、変更を反映しません。保存済みデータが壊れていたりアクセスできない場合は、元のデータを保護するため登録と削除を止めます。ブラウザの保存設定を確認し、再読み込みしてください。保存データを削除すると復旧できないため、削除前には必要な内容を控えてください。

## テスト・ビルド

```bash
npm test
npm run build
npm run preview
```

`npm test` は登録・保存・復元・月切替・絞り込み・削除・異常時の保護を検証します。`npm run build` は TypeScript の型チェックと本番用ファイルの生成を実行します。生成先は `dist/` です。`npm run preview` は生成したファイルを確認するためのサーバーです。

## ファイル構成

- `src/App.tsx`：画面と登録・削除処理
- `src/data.ts`：データ形式、保存データの読み込み・検証、集計
- `src/style.css`：PC・スマートフォン向けのデザイン
- `src/App.test.tsx`：自動テスト

依存パッケージは `package-lock.json` で固定しています。`node_modules/` と `dist/`、環境変数ファイルなどは `.gitignore` で除外しています。

## GitHub Pages で公開する

公開先は `https://sunajima.github.io/my-first-app/` です。公開設定の変更が `main` にマージされ、GitHub Actions が成功するとアクセスできます。

1. GitHub のリポジトリ画面で **Settings → Pages** を開きます。
2. **Build and deployment → Source** で **GitHub Actions** を選びます。
3. 設定を追加した PR を **Merge pull request → Confirm merge** で `main` に反映します。
4. **Actions** タブから **Deploy to GitHub Pages** を開き、`build` と `deploy` が緑色になるまで待ちます。
5. 上記の公開先 URL を開きます。

すでにマージ済みで Pages の有効化が後になった場合は、**Actions → Deploy to GitHub Pages → Run workflow** でブランチ `main` を選び、**Run workflow** を押してください。失敗した実行を開いて **Re-run all jobs** で再実行することもできます。

以後は `main` への反映ごとに、依存関係のインストール・テスト・ビルド・公開が自動で実行されます。PR ではテストとビルドだけを実行し、公開はしません。設定を保存するだけではサイトは公開されません。GitHub の契約やリポジトリの公開範囲によって Pages が利用できない場合は、Settings の表示を確認してください。

Vite の `base` は `/my-first-app/` に設定しています。開発サーバーや `npm run preview` でも、ターミナルに表示される `/my-first-app/` 付きのアドレスを開いてください。リポジトリ名や公開先を変える場合は `vite.config.ts` の `base` も変更します。

家計簿の記録は各ブラウザに保存され、GitHub Pages に送信されません。開発サーバーと公開サイトは保存領域が異なり、開発中の記録は公開サイトへ自動移行されません。
